# 建议卡换人弹层「新建」设计(检索无此人→就地命名)

日期:2026-08-02 · 前置:2026-08-02-suggestion-switch-target-design.md

背景:换人弹层检索「朱伟杰」,库里没有这个人 → 只有一行「没有匹配的人」死胡同。用户意图其实是"左侧这个说话人就是朱伟杰"。

## 语义(用户已拍板)

「新建」=把左侧说话人**就地命名**为输入的名字(`renamePerson(s.loser, 输入名)`)。声纹/样本/笔记归属原地不动、无合并日志、无 id 变更;已命名的人不再进入归属建议,这张卡随重算自然消失。不是"建空人再并入"(那需要新后端命令且多一次合并开销)。

## 交互

- 出现条件:仅建议卡「换个人」弹层;`query.trim()` 非空 **且** 库中无同名人(`!people.some(p => p.name === q)`;拼音检索命中不算重名)。满足时在 `PersonPickList` 之下渲染一行:
  `新建「{q}」并命名这个说话人`(create-row,accent 色,menu 行形态)。
- 点击:`act()` 包裹 `renamePerson(s.loser, q)`;乐观移除该建议(`tidy.suggestions` 滤掉本条,不写 dismissed——命名后建议本就不再生成,不该占一条落盘忽略);弹层随 act 收起;错误走卡片级 `actionError`(键仍 `s:loser>winner`)。
- 门禁:`disabled={busy}`(改名不挡录制,与详情页命名口径一致)。
- 与检索共存:有部分匹配(子串/拼音)时列表照常显示,create-row 依然给(名字可与候选不同);有**精确同名**人时不给(那就是该选的人)。

## 不做

详情页「合并到…」菜单不加(那里新建=改当前人名,与既有改名入口重叠);无重名二次确认(出现条件已排除同名)。

## 测试

仿真回归:检索不存在名→create-row 出现→点击→`rename_person` 调用、卡片消失、侧栏出现新名;精确同名时不出 create-row;失败路径卡片级报错。vitest/check 全绿。
