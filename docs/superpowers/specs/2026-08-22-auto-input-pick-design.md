# 录前设备检查:替用户选,不再弹专业选择题

日期:2026-08-22 · 状态:用户方向已定("帮用户选择最合适的方式进行,尽量不要让
用户做有专业性的选择");实现待当前录音结束后进行。

## 现状

开录前检测到蓝牙耳机麦克风(HFP 通话模式,上行抢带宽易断流)时,弹阻断式对话框
「这样录会丢内容…仍然录制/去改设置」——把"蓝牙通话模式带宽"这种专业判断甩给
用户,还挡在开会的必经之路上。

## 新行为:自动择优 + 事后通知,不阻断

1. **输入设备是"系统默认/自动"时**(绝大多数用户):检测到当前输入是蓝牙 HFP 麦
   且存在更好的替代(内置麦克风/有线设备)→ **本次录音自动改用替代设备**,蓝牙
   耳机继续作输出。录制页非阻断横幅一句话:「蓝牙麦克风易断流,已改用内置麦克风
   录音;耳机继续用来听。〔改回蓝牙麦〕」。〔改回〕给极少数确需蓝牙麦的场景
   (人离开电脑走动),点了本场生效并记住到设置。
2. **用户在设置里明确钉选了那台蓝牙设备**:尊重明确选择,不偷换;只显示同一条
   非阻断横幅(警示+改法),不弹窗。
3. **无替代设备**(合盖+无有线):照常录,横幅如实提示,损失照记对账。
4. 对话框整个删除;对账/遥测逻辑不变。

## 实现面(待录音结束)

- 检测处(现弹窗触发点)改为:查询可用输入设备 → 有内置/有线 → 切换本次会话的
  输入设备(仅会话级,不改持久设置)→ 事件通知前端横幅;无替代或用户钉选 → 仅横幅。
- 前端:删弹窗组件/键;录制页加横幅(带〔改回蓝牙麦〕动作);i18n 全人话。
- 测试:自动/钉选/无替代三分支;改回动作会话级生效。

## 实现期修订(如实记录)

1. **「改回蓝牙麦」按钮未做**:会话中途换采集设备要求整条采集流水线重启,收益配不
   上复杂度。逃生口 = 设置「自动避开蓝牙麦克风」开关(默认开;关掉回到弹窗提醒,
   下次开录生效)。横幅文案指向设置。
2. **应用内无"钉选输入设备"概念**(采集恒随系统默认),设计里的"尊重钉选"分支
   不存在;触发条件即"系统默认输入是蓝牙"。
3. **VPIO 逃生舱路径(capture_path=vpio)不覆盖**:Apple 通话链路自行管理设备,
   注入设备属性属另一档工作;该路径罕用,弹窗对它同样被开关抑制(择优不生效时
   风险照弹的逻辑对 VPIO 同样成立——pick 成功与否与路径无关,已知偏差)。
4. 聚合/虚拟设备不作候选(路由不明,自动换上去反而坑人)。
