# 切页继续播放 + 全局迷你播放条

## 问题

播放笔记音频时切到其他页面(设置/会议搭子/图谱等),播放会中断。

这不是技术限制。播放引擎本来就在 Rust 里(单条 cpal 输出流按 offset 混音,WebView
只画 UI),切页本不该断——断的原因是 `AudioPlayer.svelte` 的 `$effect` 清理函数在组件
卸载时调了 `player_stop`,那是一个刻意的资源回收行为。

## 目标行为

| 场景 | 行为 |
| --- | --- |
| 播放中切到**非笔记页** | 继续播,底部出现全局迷你条 |
| 播放中打开**另一篇笔记** | 停下当前,新笔记页干净的未播放状态 |
| 在笔记页上 | 迷你条隐藏(完整播放器已在页面里,不重复) |
| 点迷你条标题 | 跳回那篇笔记页 |
| 点迷你条 ✕ | 停止播放,迷你条消失 |

迷你条控件:`⏸/▶` + 只读进度 + `✕`。**进度条不可拖拽**——要精确跳转就点标题回笔记页,
那里有波形和逐句时间戳,比在一条 40px 高的条上瞄准强。

## 两个让实现变简单的既有事实

1. **`player_load` 入口就 `stop_stream`**(`player.rs`,发布锁内)。所以"打开 B 停下 A"
   由新笔记页自己的装载天然保证,**不需要写任何额外的停止逻辑**。
2. **音轨是 `TrackBytes::Mmap` 而非堆驻留**。切页后保留播放核几乎不增加 RSS,操作系统
   按需换页——"常驻内核太占内存"这个顾虑不成立。

## 方案:全局 store + layout 挂迷你条

后端零改动。前端三个文件。

### 状态 `src/lib/playback.svelte.ts`

```
noteId: string | null      // null = 无活动播放
title: string
totalMs: number
currentMs: number
playing: boolean
```

外加 `activate(note)` / `clear()`。

**`onPlayerPos` 的全局订阅移到这里**——这是本设计的关键。位置事件现在由
`AudioPlayer.svelte` 订阅,笔记页一卸载订阅就没了,迷你条的进度会僵住。放进 store
后订阅随应用生命周期存在,与哪个页面挂载无关。

### `AudioPlayer.svelte` 的改动

卸载清理里的 `player_stop` 去掉,换成把已装载的笔记登记进 store。

**generation 守卫全部保留。** 它防的是"迟到的旧装载掐掉新页面刚起的播放"
(2026-08-10 排障),与本次改动正交。动它会把那个 bug 重新放出来。

### `MiniPlayer.svelte`(新增,挂在 `+layout.svelte`)

- `⏸/▶` → `player_play` / `player_pause`
- 进度条只读
- `✕` → `player_stop` + `clear()`
- 点标题 → `goto('/notes/{noteId}')`

显示条件抽成纯函数:

```
shouldShowMiniPlayer(noteId: string | null, currentPath: string): boolean
```

`noteId` 非空**且**当前路由不是这篇笔记的详情页时显示。抽成纯函数是因为这是最容易
写错的一处(路由匹配 + 空值),必须能单测。

## 边界

- **播放自然结束**:保留内核、`playing=false`,迷你条仍在(可重播)。不自动消失——
  用户可能想再听一遍,消失了就得重新进笔记页装载。
- **录制中切页**:不受影响。录制与播放是两条独立链路,互不干扰。
- **进入另一篇笔记页**:它自己的 `player_load` 顺带停掉旧的(见上文事实 1),store
  随之更新为新笔记。
- **笔记被删/文件不可读**:`player_stop` 已经容错(`.catch(() => {})`),迷你条的
  ✕ 沿用同一纪律,失败不弹错。

## 测试

`playback.svelte.ts` 的纯逻辑走 vitest,与 `audioScheme.ts` 同款:

- `shouldShowMiniPlayer`:有播放且在其他页 → true;在本笔记页 → false;无播放 → false;
  路由带查询串/尾斜杠等变体不误判
- `activate` / `clear` 的状态迁移
- 位置事件更新 `currentMs` / `playing`

组件层不写测试——`AudioPlayer` 现有的复杂装载/换代逻辑本来就没有组件测试覆盖,
本次不改那部分语义,新增迷你条是薄 UI,真机点一遍即可。

- [ ] 点迷你条标题 → 跳回那篇笔记,迷你条隐藏,完整播放器接管且位置连续
- [ ] 播放中打开另一篇笔记 → 旧的停止,迷你条消失,新笔记未播放
