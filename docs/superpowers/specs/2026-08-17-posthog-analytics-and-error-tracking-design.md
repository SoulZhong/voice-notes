# PostHog 产品分析与异常上报 设计

日期：2026-08-17
状态：已定稿（用户逐节确认）
取代：`2026-07-12-voice-notes-telemetry-design.md`（Aptabase 方案，本设计落地后下线）

## 背景

现有遥测（Aptabase，PR#37）只能回答「有多少人在用、用了哪些功能」。它的属性被刻意限制为固定枚举与数值桶，做不了用户级行为分析、页面热点与转化漏斗——这是 Aptabase 的产品定位使然，不是配置问题。

同时，异常在别人的机器上完全不可见：631 处 `eprintln!` 全部只落本机 `app_data_dir/logs/stderr.log`，没有全局 panic hook，没有任何远端上报。2026-08-17 的「删说话人点了没反应」就是典型——后端返回了带文案的 `Err`，前端裸 `await` 吞掉，错误只走 IPC 回执，连本机日志都没有。

两件事合并解决：换用 PostHog，一家覆盖产品分析、会话回放/热图、异常上报。

## 目标与非目标

**目标**

- 远端可见性：别人机器上出了什么错、多少人碰到、哪个版本开始。
- 行为分析：页面访问、功能点击、转化漏斗、留存。
- 错误现场：异常消息、堆栈、发生位置，足以直接定位问题。

**非目标**

- 不做 A/B 实验与 feature flags（PostHog 支持，本期不用）。
- 不做用户身份关联到真实个人（只用匿名 ID）。
- 不自建任何服务端。

## 选型与部署

**PostHog Cloud 免费档**。客户端代码与自托管完全一致，只差 host 配置，将来要迁不难。

选择理由（核实于 2026-08-17）：

| | 自托管开源版 | Cloud 免费档 |
|---|---|---|
| 分析事件 | 约 10 万/月（单机上限） | 100 万/月 |
| 会话回放 | 受同一上限拖累 | 5 千条/月 |
| 异常 | 无独立额度 | 10 万条/月 |
| 机器 | 自备 4 vCPU / 16GB / 30GB+ | 无 |
| 官方支持 | 明确不支持，标注面向 hobbyist | 有 |

自托管的容量上限反而低于免费云档，且要多养一台机器、官方不背书。数据自控的诉求由「文本全遮蔽 + 属性枚举化」在客户端侧保证，而不是靠机器归属。

**Aptabase 下线**，不与 PostHog 并存——两套遥测必然出现口径分裂（`hw_gaps` 语义那次的教训）。既有 6 个事件的语义在 PostHog 重建。

## 隐私红线：变更与坚守

原设计的三条承诺，本设计动了两条。**这是产品承诺的实质变更，必须同步改对用户的文案。**

| 原承诺 | 本设计 | 为什么无法回避 |
|---|---|---|
| 不采集设备标识、不做用户级关联 | **变更**：引入持久匿名 ID | 漏斗与留存的定义就是「同一个人在时间上的序列」，无稳定标识则算不出 |
| 属性只允许固定枚举与数值桶 | **放宽**：前端事件可含页面路径与元素选择器 | 热图需要知道点击落在哪个元素 |
| 绝不包含任何会议内容 | **坚守**，且强制化 | 这条不让步 |

匿名 ID 只是 PostHog 生成的随机 `distinct_id`，不关联邮箱、设备序列号或任何真实身份，也不跨设备合并。

### 「绝不包含会议内容」如何强制

四个开关**每一个的默认值都在危险的一侧**，必须显式配置并写进防回归测试：

| 配置 | 必须值 | 不配的后果 |
|---|---|---|
| `maskAllText` | `true` | PostHog 默认**不遮**普通文本 → 录进会议逐字稿 |
| `maskAllInputs` | `true` | 默认已遮，仍显式写死，防被人改掉 |
| console 采集 | 关 | 前端 `console.log` 可能打印笔记内容 |
| 网络请求体采集 | 关 | IPC 回包里带正文 |

路由方面：`src/routes` 下动态段均为 `[id]`（`notes/[id]`、`speakers/[id]`、`hooks/[id]`），URL 里只有 note-id 与 speaker-id，不含标题或人名，可原样上报。**新增路由若把标题放进 URL，即构成红线破坏**——此约束写进模块文档注释。

后端事件属性继续沿用枚举建模，红线不放松。

### 既有缺陷：欢迎页文案与事实不符

`shell.welcome.telemetryHint` 现在写着「可在设置中关闭」，但遥测开关已于 2026-07-29 移除，设置页并无此项。**这句承诺目前是假的**，本设计一并修正：新文案如实说明采集范围（含匿名 ID 与遮蔽后的界面回放），不承诺不存在的开关。中英双语同步（`src/lib/i18n/dict/shell.ts`）。

## 架构

### 埋点分工

原设计明确「前端不埋」，理由是 MCP/CLI 触发的使用会被漏掉。该理由依然成立，但热图与漏斗必须有前端数据。改为两端都埋，边界划死：

- **后端埋「事情真的发生了」**：开录成功、转写完成、AI 整理完成。经 MCP/UDS 触发的同样计入。
- **前端埋「用户看到了、点了什么」**：页面浏览、关键按钮点击、流程放弃。热图与漏斗的原料。

两端共用同一个 `distinct_id`，否则漏斗跨不了端。**由前端生成并持久化，Rust 侧一律接收、绝不自行生成**——两边各生成一个会把同一个人算成两个人，漏斗与留存全部失真。Rust 侧在拿到 id 之前发生的事件（如启动早期的 panic）以 personless 形态上报，不补造 id。

### 客户端模块

**Rust 侧**：现有 `telemetry` 模块改为 PostHog 适配层，对外接口 `track(app, event)` 与枚举建模保持不变——调用点不动，只换实现。新增异常上报入口 `report_error(kind, err, ctx)`。

`posthog-rs`（PostHog 官方仓库）提供：

- `ErrorTrackingOptions::capture_panics = true` 配合 `init_global`，安装**进程级 `std::panic` hook**，panic 自动成为 `$exception` 事件，携带 panic 位置（file/line/column）与调用栈。
- 0.16.0 起支持上传 debug symbols，服务端符号化出可读堆栈。
- 手工捕获异常可带上下文、fingerprint 与 level。

现有各处 `catch_unwind`（refine 管线、lifecycle actor）**不需要改动**：panic hook 在展开前触发，被吞掉的 panic 照样上报。这些「出事了但应用硬撑着不崩」的场景恰恰最该被看见。

**前端侧**：`posthog-js`，负责页面事件、点击、会话回放、前端未捕获异常（`window.onerror` 与 `unhandledrejection`）。

### 脱敏

错误消息必然带出本机路径、文件名，有时是笔记标题片段。典型：

```
refine(note-140751): 写入 /Users/张伟/Library/.../notes/季度复盘会.json 失败
```

上报前机械脱敏，规则：

1. 家目录路径收敛为 `<HOME>`（消除真实姓名）。
2. notes 目录下的文件名收敛为 note-id（消除会议标题）。
3. API key 形态的串收敛为 `<REDACTED>`。
4. 连续 20 字以上的中文串整段丢弃（不截断保留前缀）——正文片段最可能以这种形态泄漏，保留前缀等于保留内容。20 这个阈值可调，但必须由测试向量钉住。

脱敏在**两端各一处**集中实现（Rust 一处、TS 一处），共用同一组测试向量，避免两边规则漂移。规则总有漏网之鱼，这是「自动脱敏 + 全自动上报」路线的已知代价，已明确接受。

## 上报面

崩溃由 panic hook 全覆盖，无需逐处标记。手工标记的关键失败点（首批约 12 处）：

| 链路 | 标记点 |
|---|---|
| 录制 | 开录失败、停录/落盘失败、采集链自愈重建 |
| 转写 | ASR 引擎异常（含既有 C++ 异常屏障）、模型加载失败 |
| AI | LLM/Agent 链路失败、apply 写回失败 |
| 存储 | 笔记写入失败、迁移失败 |
| 控制面 | MCP/UDS 分发失败 |
| 自愈 | 滞留自愈触发 |

最后一条是刻意加的：自愈能兜住问题，但**兜住不等于没发生**。它触发一次就说明有 worker 卡死，这正是在别人机器上永远看不到的那类事。

## 漏斗设计

事件体系围绕三条路径设计，否则埋了也算不出东西：

1. **新用户激活**：首启 → 授权 → 首次开录 → 首次拿到转写 → 首次 AI 整理
2. **单场录制**：开录 → 录满 5 分钟 → 停录 → 查看转写 → 编辑/导出（5 分钟这一档与既有 `duration_bucket` 的 `<5m` 边界对齐，避免同一件事两套口径）
3. **AI 功能**：进入 AI 设置 → 配置成功 → 首次整理 → 重复使用

第三条的配置环节预期流失率最高，是本期最想验证的假设。

## 限流与额度

免费档两个额度都能被刷爆：

- **回放**按会话采样，不是每次启动都录。
- **异常**按 fingerprint 每会话限流——断流风暴那类高频错误，一场会议就能打满月额度。

上报绝不影响主流程：不阻塞、不弹错、不写用户可见日志，网络不可达静默丢弃。

## 测试

- **配置形状锁定**（前端）：四个遮蔽开关的值写进测试，规格对齐既有 `payload_shape_locked`——任何改动都得先改测试，强制走一次红线审视。
- **脱敏规则**：同一组测试向量（含真实姓名、家目录路径、会议标题样本）在 Rust 与 TS 两侧各跑一遍。
- **panic hook**：触发 panic 后确有 `$exception` 上报。
- **不影响主流程**：上报失败时业务返回值与错误路径不变。
- **限流**：同 fingerprint 高频异常被折叠。
- 不做网络集成测试（投递可靠性是 SDK 职责）。

## 实施顺序

本设计覆盖的范围超出单份实施计划的合理体量，**分阶段各出一份计划**，不一次铺开：

1. spike（五条判据，判据 4 不过则砍回放）
2. 分析载体迁移 + 事件体系重做（含漏斗事件）
3. 异常上报（panic hook + 12 处标记点 + 脱敏）
4. 会话回放与热图（依赖 spike 判据 4）
5. Aptabase 下线、隐私文案修正

阶段 1 是其余全部的前置。阶段 5 必须在阶段 2 上线后才做——先让新载体收到数据，再拆旧的，避免出现「两边都没数据」的空窗。

## 2026-08-19 补齐:落地缺口一次收口

接入后系统排查了一轮「承诺过但没落地 / 换供应商时丢掉 / 默认值倒在错误一侧 / 两端各写一套」四类缺口,统一修完。

**换供应商时丢掉的**(Aptabase 插件自动带、PostHog 不会自动有):

| 字段 | 处置 |
|---|---|
| `appVersion` | 补。两端在各自 before_send 注入 `$app_version`——**注入点必须是 before_send**,各调用点覆盖不到 SDK 自装 panic hook 发的事件,而"哪个版本开始崩"正是崩溃最该回答的问题 |
| `osName` / `osVersion` | 补真值。posthog-js 从 UA 正则解析,而 WKWebView 的 UA 冻结在 `Mac OS X 10_15_7`、WebView2 冻结在 `Windows NT 10.0`(Win11 同样报 10.0)——看板上全部 mac 用户都会显示 10.15.7,而本应用的采集行为恰按 macOS 大版本分叉。改由后端 `os_info` 出唯一真值,前端经 `app_env` 取同一份盖掉 UA 那份 |
| `locale` | 补(`sys_locale`,收敛成 BCP-47 形态) |
| `isDebug` | 补。此前开发机流量与真实用户流量混在同一池且事后分不开——`internal_or_test_user_hostname` 因 Tauri 的 `tauri://localhost` 必须置 null,内外分流只剩这一条路 |
| `engineName` / `sdkVersion` | 不补。posthog-js 的 `$browser`/`$lib` 已等价覆盖 |

**承诺过但没落地的**:

- **异常限流**。「限流与额度」写明按 fingerprint 每会话限流,此前只有一句注释。两端同值实现:同 fingerprint 5 条 + 全会话 50 条双闸。单条链路刷不满、多种错各刷几条合力打满,是 2026-08-13 断流风暴的真实形态,故两道都要。
- **12 处标记点**。原只落 8 处,补齐采集链自愈重建、模型加载失败、AI 写回失败、迁移失败四类,并新增更新失败(前端经 `report_frontend_error` 白名单回后端上报——异常事件的形状只保留 Rust 一份实现)。
- **三条漏斗的关键节点**。补 `permission_checked`(漏斗 1 的授权)、`transcript_ready`(漏斗 1 的首次拿到转写,带 local/cloud 与是否空转写)、`ai_configured`(漏斗 3 的配置成功,只在跨越那一次上报)。

**默认值/框架行为倒在错误一侧的**:

- **`app_started` 永远是 personless**。它在 `setup()` 里发,早于 webview 调 `set_analytics_id`;`Event::new_anon` 每次生成随机 distinct_id 并关掉 person profile,于是每次启动都是一个全新的匿名人——留存、DAU、漏斗 1 的第一步全部算不出来。改为**压队等 id**(上限 64 条,退出时仍等不到才以 personless 发出),仍不自造 id。
- **硬崩溃完全不可见**。panic hook 只覆盖 Rust panic;whisper C++ 层的 SIGSEGV/SIGABRT、CoreAudio 崩溃、OOM 被杀、强退都不走它,且队列里没 flush 的事件一并消失——最严重的一类故障恰恰是唯一上报不到的。改为落"运行中"标记、下次启动回头看,补 `app_unclean_exit`;同一份标记顺带识别版本变化,补 `app_updated`。

**两端各写一套导致的漂移**:

- `redactEvent` 的栈帧 `filename`/`abs_path`/`module` 与 `$exception_panic_file` 在第二轮 codex review 时只修了 Rust 侧,TS 侧没跟上。
- 路径终点判据两端根本不是同一套:Rust 逐字符判断"空格后是否还像路径",TS 用 `[^\n"',;)\]]*` 一路吃到行尾。两侧号称共用同一组测试向量,但暴露这处差异的那条向量恰好只在 Rust 侧有。已把 TS 改成同算法,并把缺的向量补进两侧。

**隐私开关**。设计文档原把"设置页并无此项"当作既有缺陷、靠改文案解决;本次直接把开关补回来(`settings.telemetry_enabled`,默认开)。关掉后两端都不再发出任何事件——**包括 SDK 自装 panic hook 的**,拦在 before_send 里,那是唯一覆盖得到它的位置;前端则连 `posthog.init` 都不执行,而不是 init 之后再 opt-out(后者仍会加载录制器、仍受远端配置摆布)。欢迎页文案同步写回"可在设置中关闭"。

**未做**:符号上传(`posthog-cli` + CI secret)。release 构建的 panic 堆栈仍是不可读的地址,「错误现场足以直接定位问题」这条目标只兑现了一半。需要新的 CI secret,单独一件事做。
