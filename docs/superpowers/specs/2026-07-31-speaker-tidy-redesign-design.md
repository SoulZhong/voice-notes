# 会议搭子「整理」重设计:自动归并 + 审阅收件箱

日期:2026-07-31
状态:已获用户批准

## 背景与问题

现有整理功能散在三处:概览页可展开的「整理」卡(归属建议行 + 无样本 checkbox 清理)、
同名重复 warning 横幅、详情页 ctx-card。用户确认的四个痛点:

1. **入口太深/太散**——要进人物页签→概览页→点「开始整理」才展开;三处入口找起来费劲。
2. **逐条决策太累**——每条建议要点左试听、点右试听、对比、再点合并;小按钮密集一行。
3. **希望更自动化**——「很可能」的高置信建议还要手动确认。
4. **信息不够拍板**——只有相似度百分比和一份 3 秒试听,不敢点合并。

## 已确认的设计决策

| 决策点 | 结论 |
|---|---|
| 高置信建议 | 全自动合并 + 可撤销(需后端合并日志) |
| 拿不准的建议 | 逐条专注审阅流(一次一张大卡) |
| 队列范围 | 归属建议、同名组、无样本清理、自动归并回执全部进同一队列 |
| 撤销机制 | 逐条合并日志,单条撤销(方案 B) |
| 审阅流形态 | 独立路由 `/speakers/tidy` |

撤销为何只能走快照:`merge_with_embedder` 不可逆——质心按 count 加权平均、样本文件
超额时按多样性**永久删除**、redirect 链压扁。逆运算不存在,只能合并前落快照。

## 第一节:信息架构与入口

**一个收件箱,一个入口。** 三处分散事项全部收进 `/speakers/tidy`:

- **侧栏「概览与整理」行**:徽标数 = 队列总数(拿不准的建议 + 同名组 + 无样本条目 +
  未确认的自动归并回执)。点击仍回 `/speakers` 概览(iOS 式页签根)。
- **概览页 `/speakers`**:删除现有可展开「整理」卡与同名 warning 横幅,换成一张紧凑
  摘要卡:`整理收件箱 — N 件待处理 · M 条已自动归并`,主按钮「开始整理」直达
  `/speakers/tidy`。零待办时卡片显示"没有要整理的",不出按钮。
- **详情页 ctx-card 保留**("建议跟人走"原则不动):当前这个人的归属建议/同名重复
  仍在详情页头部就地可合并/忽略,与队列同源(`tidy.svelte.ts`),任何一处处理三处同步。

## 第二节:自动归并管线与撤销(后端)

### 新命令 `apply_confident_merges`

- 计算建议(复用 `suggest_merges`)→ 对满足条件的建议逐条执行合并:
  - 现有 strong 阈值:余弦 ≥ 0.74 或 S-Norm z ≥ 3.0(与 `isStrong` 同值);
  - loser 未命名(未命名者并入库中人物,不动已命名条目);
  - 该 pair 不在**自动合并拒绝名单**里(撤销过的 pair,落盘;见撤销语义)。
- 每条合并**前**先落日志条目;日志写入失败则放弃该条自动合并(宁可留给人工,
  不做不可撤销的自动操作)。
- 录制中不动库:`applied` 恒空,`remaining` 仍只读算出返回(审阅流只读浏览需要数据)。
- 返回 `{ applied: 回执[], remaining: 建议[] }`;回执含 journal_id、双方 id/名字、相似度。

### 触发时机(前端)

录制停止(`peopleVersion` 翻转)、应用启动、进入人物页签——复用现有 `tidy.refresh`
链路,把 `suggestPersonMerges` 调用替换为 `apply_confident_merges`。

### 合并日志

- 位置:声纹库目录下 `merge_journal/`,每条一个 JSON + 受影响样本文件的**副本**
  (合并会永久删文件,必须先拷)。
- 快照内容:双方 `Person` 完整记录、受影响 redirects 原值、双方样本文件副本、
  时间戳、来源(auto / manual)。
- **手动合并也走日志**:审阅流与详情页里手动点的合并同样落日志、同样可撤销,行为统一。
- 上限 50 条,超出淘汰最旧;撤销/确认的条目即时清除。失效条目保留至确认(供
  回执卡说明原因),其中永久性失效即时清除样本副本、可复活失效(由后续合并所致)
  保留副本。

### 新命令 `undo_merge(journal_id)`

恢复双方 `Person` 记录、还原 redirects、还原样本文件;随后前端重算建议。

### 失效规则

日志条目记录涉及的人物 id。此后任何触及这些 id 的操作——再合并、改名、删除、
新录制把新数据写进 winner——使该条**失效**:回执卡上撤销钮变灰并注明原因
(如"张三在这之后又录了新会议,不能撤了")。机制:store 层的变更入口(merge/
rename/delete/录制入库 upsert)统一调用日志的 `invalidate(涉及的 id)` 钩子。

### 撤销语义

撤销后同一 pair 的建议会重新算出来。撤销过的 pair 记入**自动合并拒绝名单**
(后端落盘,存于 `merge_journal/` 同级;仅屏蔽自动合并,不屏蔽人工建议展示),
**不再自动合并**,降级进人工队列——用户撤销就是在说"这条自动判断错了",同样的
错不犯第二次,重启应用也不犯(会话忽略集不落盘,挡不住启动时的自动归并)。

## 第三节:审阅流交互(`/speakers/tidy`)

一次一张大卡,顶部进度 `第 3 / 12 件`。队列顺序:自动归并回执 → 拿不准的归属建议 →
同名组 → 无样本条目。

### 卡片类型

- **归属建议卡**:左右两栏各展示一方——名字(可点进详情)、出现过的会议
  (`person_notes` 最近 3 场,可点)、**全部样本试听列表**(带日期,不止第一份);
  中间相似度 + "很可能"标注。动作:`合并`(主)/ `忽略` / `跳过`。
- **同名组卡**:整组呈现,默认主条目 = 最近活跃(可切换主条目),每条带试听与
  会议列表。动作:`全部并入主条目` / `忽略`。
- **无样本条目卡**:名字、最近出现、累计时长、出现过的会议。动作:`删除` / `保留`。
  卡上附带次级动作"剩余 N 条无样本条目一键清理"(走二段确认,都认不出时不用逐张点)。
- **自动归并回执卡**:`已自动归并:说话人 7 → 张三(相似度 91%)`,附双方试听。
  动作:`好`(确认,消失)/ `撤销`(失效时变灰并注明原因)。

### 键盘

`Enter` 主动作、`X` 忽略/保留、`S` 跳过、`Esc` 返回概览;数字键试听——归属建议卡/
回执卡上 `1`/`2` 播左/右方最新样本,同名组卡上 `1`-`9` 播第 n 个条目的最新样本。
试听单实例互斥,切卡/离开即停。

### 状态

- 清空态:"都整理完了" + 返回概览按钮。
- 录制中进入:顶部提示"录制中不能整理",只读浏览,动作全灰。
- `跳过`只后移本次会话的展示顺序,不改任何数据;`忽略`进会话忽略集(现有语义,不落盘)。

## 第四节:错误处理与测试

### 错误处理

- 合并/删除/撤销失败:错误横幅原样透出后端文案,卡片留在原地不跳下一张。
- 日志写入失败:放弃该条自动合并(见第二节)。
- 建议比对失败:静默清空(现有语义,建议是增值层,不打扰主流程)。

### 测试

- Rust 单测:合并日志快照/恢复往返(含样本文件)、失效规则(每种触发操作)、
  `apply_confident_merges` 的录制中拒绝与阈值/未命名筛选、日志上限淘汰。
- vitest:队列构建(四类事项排序、计数)、键盘决策逻辑(抽纯函数)、撤销后 pair
  进忽略集不再自动合并、试听互斥与切卡停止。

## 范围外

- 不改 `suggest_merges` 的比对算法与阈值。
- 不做可逆合并(墓碑方案 C 已否决)。
- 侧栏徽标形态、详情页 ctx-card 内部布局不动(仅数据源含义随队列扩展)。
