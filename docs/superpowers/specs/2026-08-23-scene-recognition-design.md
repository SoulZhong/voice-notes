# 录音场景识别(一期):特征采集、判定落盘、只提示不动行为 + 声纹断喂

日期:2026-08-23 · 状态:方案与分期经用户确认("同意")
背景:docs/superpowers/specs 同日「同源双路」诊断——两场实测 71%/86% 的 mic 段
被对方发言全程覆盖、AEC erle≈0.18dB、文本回声比对仅拦 35 段,对方整场以「我」
上屏并喂坏声纹库(五实名两两余弦 0.53~0.89)。

## 场景全集(判定目标)

1 耳机线上(理想) · 2 外放线上(回声与参考相关) · 3 同源双路(现场原声+转播,
与参考不相关) · 4 纯现场(无 system) · 5 旁听(mic 近乎无声) · 6 蓝牙通话模式(已解)
· 7 语音突显(已解) · 8 高噪 · 9 时钟异常(已解)。一期只判 1-5,8。

## 一期交付

### A. 声纹断喂(独立先行,零内容风险)
与 system 活动重叠 ≥ RESIDUE_OVERLAP_MIN(0.8) 的 mic 段**不参与回灌**
(feedback::reinforce_person 段过滤;文本/说话人归属不动)。切断「回声段喂库」
污染管道——用户手动关联的批量回灌是实测最大污染源。实时侧注册表的累积清洗
(会话质心内的污染)属二期(要动 live 管线)。

### B. 场景传感器(SceneSensor,纯逻辑可测)
滑窗(5 分钟,30s 步进)统计,输入全部来自 session.rs 已有事件流:
- mic_overlap:mic 定稿时长中被 system 活动覆盖的比例
- mic_active / sys_active:双路各自的活跃时长占比
- echo_hits:文本回声/残渣/幻觉词三门命中数(相关性代理:命中多=与参考相关)
- erle_db:AEC3 最新 erle(audio 层以原子量共享,读不到按 None)
- mic_rms_med:近/远场代理

判定规则(可解释,一期阈值标注「待校准」):
- sys_active < 5% 且 mic_active 正常 → **纯现场(4)**
- mic_active < 5% 且 sys_active 正常 → **旁听(5)**
- mic_overlap ≥ 0.6 且 (erle < 1dB 且 echo_hits 低) → **同源双路(3)**
- mic_overlap ≥ 0.6 且 (erle ≥ 3dB 或 echo_hits 高) → **外放(2)**
- 其余 → 耳机/未知(1)
连续两窗同判才切换(防抖);全程时间线记录。

### C. 落盘与提示(不动行为)
- notes/<id>/scene.json:{windows:[{start_ms,end_ms,scene,stats}], final}
- 录制页:场景稳定为 2/3 时通知条一句话(如实+改法:「像是现场+线上同源,
  对方的话可能以『我』名义出现;戴耳机可根治。二期将自动处置」),info 级不阻断
- 笔记页:停录后通知条 info 级显示最终判定(可「知道了」),用户能解释所见

### 明确不做(二期起)
按场景切行为(折叠/归属询问/门槛调整)、实时注册表断污染、事后清洗工具、
重转写按场景选引擎。一期先拿几场真会验证判定准确率。

## 测试
- SceneSensor:表驱动——四种典型窗口特征各判对;防抖(单窗不切);缺 erle 降级
- 断喂:重叠段被过滤出回灌集合;不足阈值保留;system 段不受影响
- scene.json 读写往返
