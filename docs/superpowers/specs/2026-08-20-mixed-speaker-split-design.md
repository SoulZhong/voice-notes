# 混杂说话人的隔离与拆分 设计

日期：2026-08-20
状态：待实施（经 Codex 四轮设计评审：7+2、7+3、5+1、5+2，P1 数 9→10→6→7 不收敛后**收窄承诺**，
用户裁决采纳收窄版；各轮处置见「并入的评审结论」）
前置：`2026-08-19-voiceprint-model-space-design.md`（三条模型空间不变量已落地）
关联：`2026-08-19-voiceprint-write-consolidation-design.md`（写入收口，已推迟——本设计刻意不重启它）

## 要解决的问题

一个说话人簇里混着多个人。用户看到「说话人 5」这个 chip，点开只有「改名 / 这是我 / 从会议
搭子里挑一个」——可里面是好几个人在对话，**归给谁都是错的**。

更要命的是它已经在污染声纹库：入库不等用户确认，**录制期一个簇攒够 10 秒就当场入库**领全局
人物编号。等你在界面上看出它是混的，污染早就发生了。

用户的两条诉求：

1. 能把这一簇**拆开**，每一组各自指定去处
2. **因为混杂了多人，它不该作为声纹样本、也不该作为簇头（种子）**

## 为什么承诺收窄（四轮评审的结论）

前三版设计先后尝试了三种"事后精确撤回污染"的机制：整份快照+CAS、从样本重算、
按 `(source, seen)` 摘除会话质心。四轮评审 P1 数 9→10→6→7 不收敛，每轮的新洞都指向
同一个根因：**声纹库的累积状态（主质心加权平均、会话质心环、total_ms）从来没有记过
"每一笔是谁贡献的"账**——

- 同一次 `upsert_from_session` 所有簇共用一个 `now`，同场两簇并入同一人时 `seen` 相同，无法单删
- 合并会把 loser 主质心复制成 winner 的一条**会话质心**，派生的污染没有任何标记可循
- 会话质心环只留最近 5 条，老证据被物理淘汰，"证明人物全部贡献来自某簇"不可证明

要精确就要贡献 ID + 合并血缘 + 账本崩溃一致——那就是已被五轮评审推迟的「写入收口」。
**在没有贡献账的库上承诺精确摘除，就是骗人。** 故收窄为三个做得到的承诺：

1. **隔离是硬的**：全部消费面立即生效
2. **清理是显式的**：能溯源的自动清，不能溯源的给用户看、由用户决定
3. **精确化是未来的**：贡献 receipt 从现在起开始记，账攒够了再谈精确

## 入库的两条路径（背景）

`upsert_from_session` 里：10 秒处陌生簇新建 `P<n>`（质心全来自该簇）；种子命中的簇走
`merge_centroid` 加权平均（按**段数 count**，不是时长）+ `total_ms +=` + 追加会话质心。
同一个簇一场里会**走两次**（实时 + 停录净增量）。老熟人已有样本时不写新样本，
但**无样本的老人物会拿混杂音频当第一份样本**（兜底分支）。

## 承诺一：隔离（打标即止血）

标记是**事后**打的——录音时无从知道混杂，重聚类才暴露。不动录制的实时决策路径。

两处标记，含义不同（命名避开 identify 里已有的 `mixed`＝多信道混合）：

| 落点 | 字段 | 含义 |
|---|---|---|
| 笔记内说话人 `speakers.json` | `SpeakerMeta.multi_speaker` | 本篇这个簇是混的：重转写/再入库时不入库、不写样本 |
| 库人物 `voiceprints.json` | `Person.voiceprint_quarantined` | 该人物有尚未处置完的混杂贡献：眼下不可信 |

分开的理由：混杂簇可能并进了本身干净的人（P274 郎佳奇），不能把他整个标成"多人"。
标记**不参与任何等值判定/快照比较**。`marked` 内部顺序：先隔离库人物，再写笔记标记。

### 消费面（全部路径，评审四轮无争议部分）

**读路径（不当来源）**
- `store::seed_clusters`：不当簇头（开录种子注入、Aing 重聚类、重转写）
- 自动归并 `apply_confident_merges`：目标、候选、S-Norm cohort 三处排除
- `identify`：日历召回、最近人物召回、声学召回、cohort 四处排除
- identify 应用阶段的 `MergePrior` 与自动回灌

**写路径（防复活）**
- 停录 `append_sample`：目标人物隔离中则不写
- 手工 `merge_person` / `merge_journaled`：**任一方**隔离即拒绝（否则污染直接搬进干净 winner）
- `append_sample_for_merge` 兜底截声：同上
- `undo_merge` / `restore_merged_person` / `restore_feedback` 三条回放：**保留当前隔离标记、
  不恢复两张质心表、按溯源过滤已删除的样本**（合并日志里与已删样本同 hash 的副本一并封禁）
- `rebuild_for_model`（全库）：隔离人物跳过重算并清两张质心表
- 拆分后的重新入库：只接受带匹配 `split_op_id` 的受权调用

**旧建议失效**：打标时使该笔记已生成的 `identify.json` 建议与自动应用意向失效，
最终提交前按 seq 指纹复核——否则打标前的旧建议能在打标后把混杂段灌回库。

## 承诺二：显式清理

打标后展示该簇对所涉人物的影响，清理动作全部**显式**：

### 样本

- **有溯源 receipt 的**（本设计上线后写入的）：自动删，path + content_hash 双校验，对不上拒删
- **无溯源的**（历史样本）：**不自动删**。打标 UI 列出该人物全部样本供**试听后勾删**——
  人工判断显式化，不瞎猜

**试听勾删的呈现必须诚实**（轮五 P1①——系统不知道哪份历史样本来自本篇，不能装知道）：

- 页面顶部声明：「以下是该人物的**全部历史样本**，系统无法确定其中哪份来自本篇笔记」
- 无 receipt 的样本逐份标「来源未知」；**只有** receipt 能证明来源时才标「来自本篇」
- 默认**全部不勾选**；不按"疑似污染"排序或高亮（没有依据的暗示就是误导）
- **不得用文件 mtime 推断来源**（同天录多场就串了）
- `samples_handled` 阶段落盘的内容包含"用户已确认看到上述信息缺口"

### 质心（不摘除，展示 + 二选一）

展示以下信息，**并明确标注这些都是估算、不是账目**（轮五 P1④：没有历史贡献账，
"该簇 count / 人物累计 count"证明不了两次入库、失败、redirect 之后的真实贡献）：

- 主质心污染占比**估算**（按 **count**：该簇有效段数 / 人物累计 count——不用时长，
  主质心按段数加权），标注「估算值，依据本篇段落统计」
- 该场是否留有会话质心——措辞只能是「该场存在一条会话质心」，**不能说**「来自被标记簇」
  （同场干净簇也可能写入，系统分不出来）
- 元数据残留：`total_ms` 已被累加、`last_seen` 已被覆盖（影响 identify 最近召回
  与未命名人物归并方向）

用户二选一（选择本身落盘为阶段）：

| 选项 | 语义 | 适用 |
|---|---|---|
| **接受残留** | 质心、元数据不动；解除隔离。风险说明分两截：**主质心**的污染随后续录音按加权稀释；**会话质心**（若该场留有）不稀释——它作为独立 max 种子一直有效，直到被环形上限（5 条）自然淘汰 | 占比小（常态） |
| **退回样本基线** | 逐人重算：从现存样本重建两张质心表，`total_ms` 重置为现存样本总时长、`last_seen` **置空**（不得用文件 mtime 推断）；无样本时基线 = 两张质心表空 + `total_ms=0` + `last_seen` 空。写明将丢失此后全部正常会议增量、会话变体、信道差异、回灌 | 占比大 / 人物疑似整个由该簇创建 |

**不需要 A/B 判定机制**：疑似"整个由混杂簇创建"的人物（无第二场会话质心等弱信号仅作
**提示**），其样本本就是混杂音频——试听勾删后选「退回样本基线」自动等于清空。
两条路径统一成一个显式选项，判定交给能听到声音的人。

### 逐人重算的不变量

- 不修改 `embedding_model`；用 `TaggedEmbedder` 并在 VP 锁内复核标签等于库空间
- 样本枚举、嵌入、清表、保存在同一 VP 临界区
- 只失效触及该人的合并日志（不 `invalidate_all`）；触及该人的日志 `undo_phase` 非空则拒绝
- 与全库 rebuild 共用 `REBUILD_RUNNING/PENDING` 调度协议

### 解除隔离

- 样本处置完成（自动删 + 用户勾删确认）**且**用户对质心做了二选一 → `released`
- 拆分（承诺三）不是解除的前提——只止血不整理是合法终态

## 承诺三：拆分（与污染清理解耦，无争议部分）

### 建议分组 = 拆分专用聚类模式

复用 `recluster::recluster` 的 AHC，换参数：

| | 常规 Aing | 拆分专用 |
|---|---|---|
| 碎片吞并 `MIN_CLUSTER_MS`(8s) | 无条件并入最近大簇 | **关闭**（短发言者正是要分出来的人） |
| 无嵌入的段 | 按相邻传播 | **统一进「无法判定」桶**（<1.5s、嵌入失败、轨道缺失、低质量都算） |
| 种子 | 用于命名 | 用于给每组**建议去处**（"这组像郎佳奇，0.71"） |

组数爆炸应对：低置信 singleton 默认折叠 + 批量归组，列表虚拟化，**不用硬上限强并**。
纯本地不调 LLM（`recluster` 是 Aing 流水线第二阶段，`embed_all` + AHC 都是本地函数），
没跑过 Aing 的笔记也能用。

### 交互单位下沉到「段」

每段一个「归入哪组」下拉 + 试听；并组/拆组/补组/移段都是同一控件的副产品。
**一期原子单位 = 现有 seq**：段内换人只能整段归组，文案不承诺段内拆分。

### 每组的去处

| 去处 | 语义 |
|---|---|
| 本篇已有说话人 | 只改本地归属，不碰库 |
| 库人物 | 改本地归属 + 关联 + 按该组段落走受权回灌（**可选增强**：不宣称修复质心、不作为任何解除条件、`SkippedNoSegments` 等如实展示） |
| 新说话人 | 用预分配的组 ID（见阶段机），仅本地 |
| 保持不动 | 留在原说话人 |

### 原始稿与修订稿（一期边界）

`source_seqs` 只是 seq 集合，没有字符级映射，**拆不了段落文本**：

- 某修订稿段落的**全部**非空 `source_seqs` 都去同一组 → 原位只改 speaker/person/name
- 同一段落被拆到多个组 → **整份修订稿标 stale**（已有机制，横幅提示重新 Aing），不拆文本
- 写 `aing.json` 在同一 NoteLock 内推进 revision；**发起拆分前先排空未保存的编辑器修改**

## 样本溯源与贡献 receipt（为承诺三与未来精确化）

位置：app-data 下、与声纹库同根，只受 VP 锁保护（不写 note_dir——录制 writer 整场持
NoteLock，实时入库在 worker 里持 VP 锁）。

**样本 receipt**（一对多；续录、redirect、重试都会让同一簇多次写样本）：

```
{ receipt_id, note_id, cluster_id, person_id(resolve 后), path, content_hash, at }
```

- **同锁 WAL**：VP 锁内 intent → 写 WAV → complete。启动恢复**三分支**：文件在且 hash 符
  → 补 complete；不在 → 丢 intent（清同槽 `.tmp`）；**在但 hash 不符 → conflict 封禁槽位**，
  不认领不删除留人工。落盘顺序 intent fsync → WAV 落位及父目录 fsync → complete fsync
- 合并迁移样本时同步迁移 receipt；删除双校验；**不按大小上限淘汰**
- **顺带修既有 bug**：停录写样本的存在性检查用未 resolve 的 pid（笔记持 loser id 时误判
  "无样本"、把样本写到已有样本的 winner）——检查前先 resolve，并与 append 收进同一临界区

**质心贡献 receipt**（只记不用，定位是**辅助诊断证据**——轮五 P1③）：

```
{ receipt_id, note_id, cluster_id, resolved_person, source, count, total_ms, created_person, vec_hash, at }
```

一期**不基于它做任何撤回承诺**。也**不宣称**"攒够了自然精确"：真正的精确化还需要
可取回的贡献向量（hash 无法恢复被环淘汰的向量）、合并血缘、与质心写入共同提交的
崩溃一致性——那是写入收口的范畴。这份 receipt 的一期价值是：出问题时能回答
"这个人物历史上被哪些笔记的哪些簇写过"，仅此而已。

## 阶段机

横跨 `speakers.json`、声纹库、样本文件、段落归属四种资源，阶段必须落盘。

```
mode = quarantine_only:  plan → marked → samples_handled → residual_decided → released → done
mode = split_commit:     plan → reserved → marked → samples_handled → residual_decided
                         → segments_reassigned → reenrolled → released → done
```

- **`plan` 先于一切副作用落盘**（含预分配组 ID、note revision、seq/source/时间戳指纹、
  每 seq 原 speaker、目标组与目标人物、涉及的 receipts、`split_op_id`、
  每项资源的 expected-before 内容哈希）。轮四 P1④：占号不能在计划之前——
  否则占号后崩溃留下无法归属的空表项，且占号自身已改变 before 哈希
- **`reserved`**：计划落盘后，NoteLock 内写入空预留表项真占号；表项带 `split_op_id`
  所有权；取消/第三态清理时仅在"仍为空且未被引用"时 CAS 删除
- **`samples_handled` / `residual_decided`**：承诺二的两项义务各自成为显式幂等阶段
  （轮四 P1⑤：不能让"接受残留"路径推进到 released 却没有落盘证据）
- **恢复三态判别**：每项资源与 expected-before 比对——等于 before → 重做；等于计划后态
  → 推进；**第三态（用户或其他 writer 动过）→ 停止提交、保持隔离、作废计划**提示重建
- `segments_reassigned`：持 NoteLock 批量改派，只用 `reserved` 的显式 ID，不走 `"new"`
- **取消是持久化路径，不是一句 CAS**（轮五 P1②——否则用户占号后放弃并退出，
  启动恢复反而把拆分继续做完）：`cancel_requested → cancelled` 两个落盘阶段。
  先落取消意图；再在 NoteLock 内原子清理本 op 的全部**空且未被引用**的预留表项
  （"被引用" = `segments.jsonl` 有段 speaker 指向该 ID，或 `aing.json` 段落引用该 ID;
  plan 自身不算引用）；最后落 `cancelled` 终态。崩溃恢复见到 `cancel_requested` 重做清理。
  **取消边界**：`marked` 之后取消 → 转成 `quarantine_only` 模式继续清理义务（隔离与
  样本处置不因放弃拆分而豁免）；`segments_reassigned` 之后**不可取消**，只能前滚
- `quarantine_only` 的 `done` 是合法终态；`split_commit` 的非 `done` 且非 `cancelled`
  启动续跑
- 阶段写盘失败 → 重做该步（先做后记，与 `undo_phase` 同一取舍）

## 并入的评审结论

轮一（7×P1+2×P2）、轮二（7×P1+3×P2）：处置摘要见 git 历史中的前两版文档；
关键遗产——隔离消费面清单、样本溯源 WAL、拆分专用聚类、段级交互、修订稿边界、
既有 resolve bug 的发现。

轮三（5×P1+1×P2）：权重口径改 count、回灌降级为可选增强、A/B 判定问题暴露、
prepared 三态判别、修订稿"不拆文本"边界、WAL 第三分支。

轮四（5×P1+2×P2）与最终裁决：

| 发现 | 收窄版处置 |
|---|---|
| P1① 合并派生会话质心无血缘可循 | **不承诺摘除 → 问题不存在**；残留归入"接受/退回基线"二选一 |
| P1② `(source,seen)` 非唯一键，同场误删 | 同上消失；贡献 receipt 带 `vec_hash` 只为攒账 |
| P1③ A/B 判据不可证明 | **取消判定机制**：试听勾删 + 退回基线统一覆盖，判定交给人 |
| P1④ 占号先于计划的矛盾 | `plan → reserved` 两阶段，预留项带 op 所有权 |
| P1⑤ B 类清理义务无阶段 | `samples_handled` / `residual_decided` 显式阶段 |
| P2① 元数据残留未覆盖 | 并入"接受残留"的展示（total_ms/last_seen 明说）；退回基线时重置 |
| P2② 摘除后环形少一条 | 不摘除 → 消失 |

轮五（4×P1+2×P2，收窄版验收）：

| 发现 | 处置 |
|---|---|
| P1① 试听勾删会误导删干净样本 | 顶部声明信息缺口、逐份标「来源未知」、默认不勾、不排序不高亮、不用 mtime、`samples_handled` 记录用户确认 |
| P1② `reserved` 后无持久化取消路径 | `cancel_requested → cancelled` 两阶段;引用集合定义;取消边界（marked 后转 quarantine_only、segments_reassigned 后只能前滚） |
| P1③ "未来完整账/自然精确"言过其实 | 降级为「辅助诊断证据」,写明真精确化仍需向量取回+血缘+共同提交 |
| P1④ 展示把估算写成事实;稀释说明不分载体 | 全部标注估算与不可归因;主质心稀释 / 会话质心独立 max 种子分开说明 |
| P2① `last_seen` 重置无定义 | 置空;空样本基线三元组定义;禁 mtime |
| P2② 测试矩阵不全 | 逐项补齐（见「测试」） |

Codex 轮五结论：「隔离消费面和退回样本基线的总体方向已经自洽；上述 P1 收口后即可进入实施计划。」

## 数据与兼容

- `SpeakerMeta.multi_speaker`、`Person.voiceprint_quarantined`：`#[serde(default)]`，无迁移
- 样本 receipt + WAL、质心贡献 receipt、拆分阶段记录：新文件，与声纹库同根，只受 VP 锁
- 无溯源的老样本：永不自动删，只走试听勾删

## 测试

- 隔离读路径：隔离人物不出现在 seed_clusters / 归并候选与 cohort / identify 四类召回
- 隔离写路径：向隔离人物 append_sample 被拒；任一方隔离的合并被拒
- 复活防线：勾删样本后 `undo_merge` 回放，同 hash 日志副本不落地；全库 rebuild 对隔离人物只清空
- 溯源 WAL：三分支启动恢复；hash 不符拒删并封禁；合并后 receipt 仍可定位
- resolve bug 回归：持 loser id 的笔记停录，样本不重复写到 winner
- 阶段机：plan 先于一切副作用；reserved 占号后并发 `"new"` 不撞号；三态判别第三态停止提交;
  `quarantine_only` 的 done 不触发恢复；批量改派重试不产生新 S 编号
- 退回基线：两张质心表由样本重建，total_ms/last_seen 重置；`undo_phase` 非空的日志令其被拒
- 拆分聚类：3s 短发言者独立成组；几十个互不相似 2–4s 噪声段全部进折叠区不爆组
- 修订稿边界：段落 source_seqs 跨组时整份标 stale，不产生文本拆分
- 笔记侧标记：`multi_speaker` 的簇在重转写/再入库路径不入库、不写样本
- 旧建议失效：打标后旧 `identify.json` 建议不可再应用;最终提交按 seq 指纹复核
- 三条 restore 回放：隔离标记保留、质心表不被恢复、同 hash 样本副本被过滤
- 受权回灌：`split_op_id` 错误或缺失的回灌被拒
- 取消协议：`cancel_requested` 崩溃后恢复重做清理;被引用的预留项不被 CAS 清掉;
  marked 后取消转 quarantine_only 且清理义务仍执行
- 试听勾删呈现：无 receipt 样本标「来源未知」、默认不勾选（组件测试）
- 现有 1408 条 Rust 测试不得变红
