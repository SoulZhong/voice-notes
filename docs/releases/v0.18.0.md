# v0.18.0 发布说明

v0.17.0 之后 7 个 PR:能导入本地录音了,正文里的实体看得见、能合并,AI 整理少烧四成冤枉 token,大笔记点开不再卡。

## 音频导入:本地录音也能变笔记

- 侧栏「导入音频」:选一个本地录音文件 → 建成一篇笔记 → 后台转写、认人、AI 整理,与停录后的链路完全一致。MCP 侧同步加 `import_audio` 工具。
- 转写跑着的时候也能改与会人员、标题、日程了:meta.json 拆出自己的锁,不再被转写的十几分钟整篇锁死(此前手动重转写一直如此,只是导入让它特别显眼)。

## 关键实体二期:看得见、并得了

- **正文着色**:提及处按实体类型上色,与实体行的 chip 同色——此前只有鼠标悬停才显形,看着像没识别。
- **合并**:改名撞同名时可直接合并,败方的名字转为别名、提及和关系改挂胜方,什么都不丢。
- **别名可见可编辑**:一排带 × 的小药丸 + 加别名输入框,加了正文立刻多出高亮。
- 实体行与说话人行视觉上分开。

## 认人

- 「取消关联」点名说关的是谁(「取消关联「张三」」),并说明不删段落、不造新人、已入库样本退回。
- 修:取消关联后名字还挂在 chip 上;取消后声纹建议又把刚否掉的人原样劝回来。

## AI 整理更省、更稳

- 失败时正文往往早已写完整、只是被后面的字段写坏连坐丢掉——现在把完整的正文抢救回来(实测失败里 63% 可救)。
- 术语表加卫生门,一块输出退化不再顺着传染整场。
- 人物关系摘出分块请求:此前所有笔记的关系阶段一篇都没成功过,现在单独跑、单块失败不连坐。

## 界面与性能

- **大笔记点开不卡了**:3000 段级的笔记主线程卡顿 280ms → 65ms(徽章查表、保存基线惰性、只排版可见部分、后端命令离开主线程)。
- 逐字稿工具条:二段确认改成锚定浮层,不再一点就把操作栏顶变形;「重新分析」正名为「重新转文字」,并写明原稿备份到哪;两颗按钮统一成一套样式。

## 工程

- 修 windows-check:坏缓存自持导致 master 从 9/18 起一直红,build 前按产物在不在自愈。

## 发布步骤(留档)

1. `git tag v0.18.0 && git push origin v0.18.0` → release.yml 出 dmg/exe/updater(约 20 分钟)
2. `gh release edit v0.18.0 --notes-file docs/releases/v0.18.0.md`,标题「v0.18.0 · 音频导入、实体看得见、点开不卡」
3. 真机冒烟:导入一段本地录音(转写中改与会人员);正文实体着色/合并/别名;取消关联后 chip 名字清掉;大笔记点开流畅度与定位/跟播滚动;从 0.17.0 一键更新
