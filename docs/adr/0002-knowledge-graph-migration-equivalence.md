# 知识图谱迁移保持语义等价，关系补建显式执行

数据目录迁移后，图谱视图必须保持迁移前的语义结果：来源数据、人工治理结果、实体、提及、关系及关系证据不能因为目录变更而静默丢失。笔记 `aing.json` 与 `knowledge-overrides.json` 是来源真值；`graph.sqlite` 是由它们派生的索引。因此迁移可以复制索引，也可以在必要时从来源重建；但重建必须能够恢复来源中已有的关系与人工治理结果。

对于来源中本来没有关系的历史笔记，不在迁移过程中隐式调用 AI。应用应明确标记为“关系待补建”，由用户在配置关系分析器后，通过预览、确认的关系补建流程生成关系。关系补建只写关系及证据，不修改正文、实体、段落顺序，并支持按笔记记录失败与重试。

## 现状与原因

当前迁移只搬运笔记和声纹数据，图谱索引随后重建。实体索引可以恢复，但历史 `aing.json` 中没有关系时，重建得到的关系数为零，图谱页面容易把它误解成筛选无结果。这暴露出迁移等价性和状态提示没有被完整表达。

## 方案

采用混合迁移策略：迁移 `knowledge-overrides.json` 等治理来源，优先复制并校验现有图谱索引，保证正常迁移后的即时等价；索引缺失、损坏或版本不兼容时，从来源数据原子重建。索引通过来源摘要校验（而非只比较数量），重建后再校验实体、提及、关系和证据统计，并在关系为零时明确区分“来源无关系/待补建”与“筛选无结果”。迁移期间暂停录制、Aing、关系补建等会修改来源或索引的操作。迁移采用旧目录保留、校验与指针切换成功后再清理旧目录的提交语义。图谱视图提供索引重建、关系补建预览、分析器配置、失败重试和状态诊断。

## 取舍

- **只重建**：实现简单、能避免搬运 SQLite 快照，但会把“来源已有关系”和“来源没有关系”混在一起，且重建成本更高。
- **只复制索引**：迁移快，但无法处理损坏、版本升级和索引与来源不一致。
- **混合策略**：需要校验和回退逻辑，但同时保留迁移速度与可恢复性，且能把派生索引、来源数据和人工治理结果的边界说清楚。

## 后果

- 迁移流程需要把图谱索引视为可复制、可校验、可回退的派生快照，而不是永远排除在迁移之外。
- 图谱视图需要区分“无关系”“筛选后无结果”“索引重建中”“关系待补建”和“索引异常”，并提供对应恢复动作。
- 关系补建是显式、可确认、可重试的 AI 操作，不属于普通目录迁移的隐式副作用。
- 迁移失败时旧目录继续可用；只有新目录完成校验并切换指针后才进入旧目录清理阶段。

## 落地状态（2026-11-25）

本文写于 2026-11-16，「现状与原因」描述的是当时的代码。之后实际落地的部分：

- **已落地**：迁移改为整根搬（PR #276），`knowledge-overrides.json`、`graph.sqlite` 以及此后新增的数据文件都会随迁移过去，不再依赖逐项登记的名单。
- **已落地**：迁移与 Aing、关系补建双向互斥——它们在跑时不许迁移；迁移在跑时不许起跑它们。
- **未落地**：索引的来源摘要校验与损坏时自动重建、图谱视图的五种状态区分、「关系待补建」标记。迁移后目前是原样复制索引（只校验复制本身是否完整），不核对索引与来源是否一致。
