# 整理功能四项跟进设计(重新整理 / 失效目标保险 / 拆回原身份 / 宽度利用)

日期:2026-08-01 · 分支:feature/speaker-tidy-redesign · 前置:2026-07-31-speaker-tidy-redesign-design.md

背景:真机数据(126 人、23 条回执、16 条失效)暴露四个问题——没有手动重跑入口;失效存档回执铺满首屏且被误读为"待办的合并";失效条目里被并入方的快照只能听、无法拆回;概览页 44rem 列宽在宽窗下留大片空白。

## 1. 重新整理(仅重算)

「分析说话人」标题行右侧加「重新整理」mini 按钮(与「一键确认全部」同排工具区)。点击=手动触发一次 `tidy.refresh()`(后端 `apply_confident_merges`:高置信自动归并+重算剩余建议)。运行中按钮置灰,复用既有「正在比对声纹…」提示。忽略/保留处置名单**不动**;撤销产生的自动归并拒绝名单照常生效。录制中可点(后端此时只读比对,不落库)。无新后端命令。

## 2. 失效目标双重保险 + 存档折叠

**过滤保险(前端兜底)**:`buildTidyQueue` 过滤 loser 或 winner 不在当前 people 的建议;`tidy.involving()` 的消费方(详情页上下文卡)同样要求对方仍在库。后端建议本就按当前库现算,此层只补时序窗口。纯逻辑,配 vitest。

**存档折叠**:失效回执(`invalid_reason ≠ null`)移出主队列,收进队列**末尾**一个横跨整行的折叠组:

- 收起态(默认):一行「N 条已存档 · 展开逐条核对」+「一键确认全部」按钮。
- 展开态:逐张渲染既有存档卡(快照试听/知道了/新增的拆回按钮)。
- 会话内记住展开态(页面局部 state 即可,不落盘)。

**徽标口径变更**:侧栏「概览与整理」徽标与「N 件待处理」摘要**不再计入存档条**——徽标=待拍板的活(有效回执+建议+同名组+无样本)。存档数只出现在折叠组行内。

## 3. 拆回原身份(restore_merged_person)

**语义**:对失效日志条目,把被并入方按合并前快照重建为**原编号**的独立说话人。历史笔记中原属他的段落随 redirect 还原重新归他;之后录制凭恢复的声纹重新认出他;该 pair 进自动归并拒绝名单;不动 winner(其质心中已混入的贡献不抽回,由后续录制自然纠正——卡上文案说明)。

**后端**:`voiceprints.rs` 把 `undo_merge` 的"恢复 loser"半边(重建 Person、回填样本副本 `restore_samples`、还原 `redirects_to_loser`、双向拒绝名单、删日志条目)抽成共用路径;新命令 `restore_merged_person(journal_id)`:

- 仅接受 `invalid_reason.is_some()` 的条目(有效条目走既有 `undo_merge`,拒绝时报「该条仍可直接撤销」)。
- 录制中拒绝,口径同 `undo_merge`。
- loser 原 id 不会撞库(id 单调分配,合并后不复用),防御性校验存在即报错。
- **不** `revive_invalidated_by`:拆回不撤销那次合并本身(winner 原状保留),被它连带失效的链上条目前置状态未还原,复活它们会造成"可撤销"假象——此语义仅属 `undo_merge`。
- 返回恢复的 person id(前端跳转/提示用)。

cargo 单测:重建后 registry 有 loser、redirect 指回、denylist 含 pair、journal 条目消失;有效条目被拒;录制中被拒。

**前端**:存档卡动作区=「拆回独立说话人」(accent)+「知道了」;成功后乐观收起该卡、`bumpPeople`,错误走卡片级 `actionError`。`people.ts` 加 `restoreMergedPerson(journalId)`。

## 4. 自适应多列卡片流(仅概览页)

- 容器:`max-width: 44rem` 放开为全宽(保留 1.5rem 内边距);引导语 `.desc` 保持 40rem 可读列宽。
- 卡片列表 `.stack`:`display: grid; grid-template-columns: repeat(auto-fill, minmax(26rem, 1fr)); align-items: start;`——1800px 约 3 列,窄窗自动退单列;DOM 序即队列序,阅读顺序逐行。
- 横跨整行(`grid-column: 1 / -1`):错误横幅、录制中横幅、撤销条、存档折叠组、工具行。
- 统计行维持 flex(自然不满行不难看)。详情页 44rem 不动。

## 错误处理与一致性

全部动作沿用本轮既有约定:卡片级 `actionError` 就地展示、`act()` 成败都对账、sticky 顶部横幅承接全局错误。拆回与一键确认在录制中置灰(合并/删除/撤销同口径),重新整理与展开/收起不受录制限制。

## 测试

- vitest(TDD):队列过滤失效建议;存档/待办分组与徽标计数口径;(既有测试回归)。
- cargo(TDD):`restore_merged_person` 四态断言 + 两个拒绝路径。
- 无头回归(IPC 仿真层):重新整理按钮、折叠展开/一键确认、拆回全流程、多列布局截图;真机人工看布局与拆回一例。

## 明确不做

- 存档组展开态持久化(会话级足够)。
- 「重出已忽略项」召回入口(用户拍板:重新整理仅重算)。
- winner 质心去污(数学上不可逆,靠后续录制收敛)。
- 详情页宽度改动。
